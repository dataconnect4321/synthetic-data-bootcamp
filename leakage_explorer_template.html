Leakage by column

How far apart the two groups' distributions of each column are: the total-variation distance (TV), where 0 means identical. A classifier that sees only this column guesses with balanced error (1 − TV)/2 at best (second axis row), so a balanced error of 0.5 means no leak. Click a row to show its histogram below.

The share of the uncertainty about that knowing this column removes: I(; column) / H(), from 0 (no information) to 1 (the column determines ). Leakage through all columns at once

Repairing columns one by one can leave readable from combinations of columns, so this asks a classifier (the scorer's gradient-boosted trees, paper_metrics.py) to recover it from every other column. For both measures 0.5 means no leak. Balanced error: predicting the table's own column (3-fold, mean of 10 seeds). Folded tstr: trained on the table, tested on real held-out people (fold 0 test rows), folded as 0.5 − |BER − 0.5| so that a flipped label also counts as a leak.

How this is simulated: each [ × column] count table gets Gaussian noise with an equal share of the zCDP budget ρ (δ = 1e-5). Then each group's distribution is moved τ of the way to the pooled distribution using the transport plans of aim_fair/fair_aim.py (monotone for binned numerics, minimal-move for categories). This works on marginals only. It does not fit Private-PGM, mask proxies or apply consistency rules. With Equal split it spends the budget on tables, where real AIM spends it on many more, so real noise is larger; AIM's starting σ uses the noise real AIM starts with at the same ε instead (AIM then halves σ on some tables and combines several noisy tables in its model fit, so neither setting is exact). Repairing each column separately does not remove leakage through combinations of columns: the real AIM hybrid's release still teaches the protected attribute slightly (folded tstr 0.43–0.49 across the four datasets, not 0.5; see RESULTS.md and results/datasets_summary.csv).
